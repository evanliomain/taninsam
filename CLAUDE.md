# Taninsam

A zero-dependency functional TypeScript library built around a `chain` mechanism. Every public
function is curried: it takes its configuration and returns the function to apply on the data.

```typescript
chain([1, 2, 3, 4, 5, 6])
  .chain(filter(x => 0 === x % 2))
  .chain(map(x => x ** 2))
  .chain(sum())
  .value(); // 56
```

## Three invariants — never violate them

1. **No breaking change, ever.** Users must be able to upgrade any version without fear.
   Names, signatures, exports and observable behaviour of published functions are frozen.
   Extend with overloads and optional parameters; never modify. See the `api-stability` skill.
2. **Zero runtime dependencies.** `dependencies` in `package.json` stays empty. `src/` may only
   import from `src/` through relative paths — no npm package, no Node built-in, no polyfill.
   devDependencies (build, test, lint) are fine.
3. **100% coverage and the highest possible mutation score.** vitest thresholds are 100% on
   branches, functions, lines and statements. Stryker runs on every PR.

## Workflow

Documentation Driven then Test Driven, in this order, no shortcut:
signature + TSDoc → unit tests → implementation. The `new-function` skill walks through it.

## Commands

- `yarn gen` — scaffold a function (plop). Non-interactive: `npx plop function "take last"`
- `yarn test` — run the suite once
- `yarn test:watch` — watch mode
- `yarn vitest run --coverage` — suite + coverage summary
- `yarn lint`, `yarn lint:pre-commit` (autofix)
- `yarn stryker` — mutation testing; html report in `dist/stryker-reports/report.html`
- `yarn build:compiled && yarn build:bundle` — build (there is no `yarn build`, despite the README)

`yarn test:ci` is **watch mode** outside a CI environment and will hang. Use
`yarn vitest run --coverage` locally.

## Layout

One folder per function, kebab-case, exposing the camelCase function:

```
src/<kebab-name>/
  index.ts               export * from './<kebab-name>';
  <kebab-name>.ts        the function and its TSDoc
  <kebab-name>.spec.ts   the tests
  __snapshots__/         generated by vitest
src/taninsam.ts          public barrel, regenerated by plop — alphabetical
src/@types/              shared types (Links, Iteratee, Chain, ChainFn, Result, Identity…)
src/.internal/           helpers that are never exported (log)
```

`src/group-by/` is a stale, empty folder. Because plop rebuilds the barrel from the folder
listing, `yarn gen` re-adds `export * from './group-by';` and breaks the build — remove that
line after every generation.

## Style

- Prettier (single quotes, `arrowParens: 'avoid'`) + eslint with sonarjs; autofixed on commit.
- **Yoda conditions everywhere**: `0 === x % 2`, `undefined !== initialValue`, `1 !== s.length`.
- `ReadonlyArray<T>` always, never `T[]`.
- Pure functions only: copy before mutating (`array.slice().sort(…)`, object spreads).
- `no-magic-numbers` permits only `0`, `1`, `-1` — name every other constant.
- Blank line before a `return` that follows other statements.
- Build a function out of existing taninsam functions when it reads well (see `cast-to`,
  `partition`, `hash`, `entries`).
- English only — code, documentation, tests and commit messages.

## Commits

Conventional commits (commitizen) drive semantic-release: the message format *is* the release
process. See the `commit-message` skill. `yarn commit` is interactive, so write the message by
hand with `git commit -m` instead.
